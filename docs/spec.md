# 「我们约会吧」定稿方案 v1

2026-11-16 由总管访谈用户后定稿。范围变更必须先改这份文件，再改代码。

## 一句话

情侣两人各自填问卷说清「不吃什么、不想玩什么」，绑定成一对后，用掷骰子、各抽一半、盲盒、刮刮乐来随机决定这次约会做什么，每人有有限次否决机会。双方都确认后，AI 把结果排成行程，可以导出长图或分享链接。

## 已拍板的决定

| 项 | 决定 |
|---|---|
| 客户端 | uni-app（Vue3 + Vite + TS，CLI 工程）。首发**安卓 App**，由用户自己用 HBuilderX 云打包。开发和验收用 H5 版（375 宽） |
| 后端 | Node 20+ / Express 5 / better-sqlite3，部署到用户的宝塔服务器，走子域名 + HTTPS（上线前要再问用户） |
| AI | DeepSeek（OpenAI 兼容接口，`deepseek-flash`，请求里带 `thinking: {type: "disabled"}`；`deepseek-chat` 已于 2026-07-24 下线），Key 从环境变量 `DEEPSEEK_API_KEY` 读取 |
| 登录与绑定 | 昵称 + 性别注册，换来设备 token 和一个恢复码；绑定用 6 位邀请码 |
| 城市 | 以成都为主，另外收录一些不限城市的通用点子 |
| 知识库 | 先从公开网页收集成都约会内容，用自己的话改写成点子卡，再用 AI 生成补足 |
| 随机玩法 | 掷骰子、双人各抽一半、盲盒抽卡、刮刮乐（v1 不做转盘） |
| 选择规则 | 每次约会每人 2 次否决重抽的机会，用完就必须接受 |
| 导出 | 长图（保存到相册）+ 分享链接（后端渲染的公开网页） |

## 数据：点子卡（data/ideas.json）

```json
{
  "id": "cd-001",
  "title": "鹤鸣茶社喝盖碗茶、掏耳朵",
  "kind": "eat | play",
  "category": "美食 | 小吃 | 饮品 | 景点 | 手作 | 娱乐 | 运动 | 文艺 | 夜生活 | 宅家",
  "city": "成都 | 通用",
  "area": "锦江区（通用卡为空）",
  "address": "人民公园内（通用卡为空）",
  "budgetPerPerson": 60,
  "durationMin": 90,
  "timeOfDay": ["morning", "afternoon", "evening", "night"],
  "tags": ["辣", "海鲜", "生冷", "高体力", "刺激", "恐怖", "人多", "户外", "早起", "排队", "酒精"],
  "rarity": "common | rare | surprise",
  "description": "一两句话，自己的话写，不照抄原文",
  "source": "来源 URL（AI 生成的写 ai）"
}
```

- `kind=eat` 是吃喝，`kind=play` 是玩。目标数量：成都卡 ≥150 张，其中 eat 和 play 大约各一半；通用卡 ≥50 张。稀有度大致按 common 70%、rare 25%、surprise 5% 分配。
- `tags` 只用上面这份固定词表，问卷选项靠它来排除卡片。
- `data/tasks.json` 是刮刮乐小任务，≥30 条，格式 `{ "id", "text" }`，例如「给对方拍一张最丑的照片」。

## 问卷（客户端写死，不调 AI）

| 问题 | 选项 → 排除的 tag |
|---|---|
| 你不吃什么？（多选） | 辣→辣、海鲜→海鲜、生冷→生冷、酒→酒精 |
| 你不想做什么？（多选） | 太累/走太多路→高体力、刺激项目→刺激、恐怖→恐怖、人挤人→人多、风吹日晒→户外、早起→早起、排长队→排队 |
| 还有什么特别不喜欢的？ | 自由文本，只传给 AI 排行程时参考 |

两人选中的排除 tag 取并集，抽卡时只要命中其中任意一个 tag 的卡片都不参与抽取。

## 约会流程（一个 date 会话，两台手机看到同一份状态）

1. 任一方发起「新约会」，选日期和大致出发时间。
2. **掷骰子定预算**：点数 1–6 对应人均预算上限 50/100/150/200/300/不限，超过上限的卡不参与抽取。
3. **双人各抽一半**：男生抽吃（eat），女生抽玩（play）；如果两人性别相同，邀请方抽吃。每人只能在自己手机上抽自己那一半，抽出的卡对双方都可见。
4. **盲盒（可选）**：再抽一张任意 kind 的卡加到行程里，按稀有度加权（70/25/5）。翻卡时有动画，稀有度用颜色区分。
5. **刮刮乐**：刮开得到一条情侣小任务。
6. **否决**：任何一张卡都可以否决并重抽，每人每次约会 2 次机会，两人的次数分开计算。
7. 双方都点「就这么定了」以后，后端调 DeepSeek 排行程：时间线、两段之间怎么走、小贴士。调用失败或超时（15 秒）时，按规则兜底：按卡片的 durationMin 顺序排时间，每段之间留 30 分钟路程。
8. 行程页可以导出长图（保存到相册），也可以复制分享链接。

**随机数一律在服务端产生**，两台手机都用每 2 秒轮询一次 `GET /api/dates/:id` 的方式同步，不用 WebSocket。

## API（JSON，`Authorization: Bearer <token>`）

| 方法 路径 | 作用 |
|---|---|
| POST /api/users `{nickname, gender}` | 注册 → `{token, user, recoveryCode}` |
| POST /api/users/recover `{recoveryCode}` | 用恢复码找回 → `{token, user}` |
| GET /api/me | 我、对象、问卷是否已填 |
| PUT /api/me/preferences `{excludeTags[], note}` | 保存问卷 |
| POST /api/couple/invite | 生成 6 位邀请码（24 小时有效） |
| POST /api/couple/join `{code}` | 用邀请码绑定 |
| DELETE /api/couple | 解绑 |
| POST /api/dates `{date, startTime}` | 新建约会 |
| GET /api/dates/:id | 约会完整状态（轮询用） |
| GET /api/dates | 本对情侣的历史约会 |
| POST /api/dates/:id/dice | 掷骰子定预算（每次约会只能掷一次） |
| POST /api/dates/:id/draw `{game: "split" \| "blindbox"}` | 抽卡（split 由服务端按身份决定抽 eat 还是 play） |
| POST /api/dates/:id/scratch | 刮刮乐 |
| POST /api/dates/:id/veto `{slot}` | 否决某张卡并重抽，扣自己 1 次机会 |
| POST /api/dates/:id/confirm | 我确认；两人都确认后生成行程 |
| GET /s/:shareId | 公开分享页（服务端渲染的 HTML，手机浏览器打开就能看行程） |

错误统一返回 `{error: "给用户看的中文提示"}` 加对应的 HTTP 状态码。

## 界面

页面：引导注册 → 问卷 → 绑定（显示我的邀请码 / 输入对方的邀请码）→ 首页（发起约会、历史约会）→ 约会进行页（按流程分步：骰子、抽卡、盲盒、刮刮乐、确认）→ 行程页（导出长图 / 复制链接）→ 我的（改问卷、解绑、查看恢复码）。

风格：温暖、俏皮，主色珊瑚粉，卡片翻面、骰子滚动、刮涂层都要有动效。不要做成一般的后台风格。

## 不做（v1）

转盘、AI 问卷追问、高德地图实时 POI、小程序端、iOS、推送、聊天、支付、多城市切换。

## 验收标准

两个浏览器窗口（375 宽）分别注册一男一女 → 各自填问卷（男选不吃辣）→ 用邀请码绑定 → 一方发起约会 → 掷骰子 → 各抽一半 → 抽盲盒 → 刮刮乐 → 男方否决一次后重抽 → 双方确认 → 出现行程 → 导出长图成功 → 分享链接在无痕窗口能打开。全程抽到的卡都不含「辣」，另一个窗口 2 秒内能看到同步变化。没配 DeepSeek Key 时也能用兜底行程走完。
